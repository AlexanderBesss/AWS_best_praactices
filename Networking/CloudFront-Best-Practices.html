CloudFront Best Practices

A well-configured CDN is critical for delivering low-latency content to global audiences, reducing origin server load, and defending against traffic spikes and DDoS attacks. CloudFront extends AWS's edge network to over 400 locations, making it the backbone of performant, secure, and cost-effective content delivery.

Note

If a cache policy has a minimum TTL greater than zero, CloudFront can cache for at least that duration even when the origin sends Cache-Control: no-cache, no-store, or private. Use a zero minimum TTL for responses whose origin directives must prevent caching.

Use Cases

Each event type in the CloudFront request-response lifecycle offers a distinct hook for request or response manipulation.

Function TypeUse CaseExample
Viewer RequestModify incoming requestsA/B testing, geo-redirect
Viewer ResponseModify outgoing responsesAdd security headers
Origin RequestModify requests to originHeader transformation
Origin ResponseModify responses from originError page customization
Tip

Default to CloudFront Functions for simple header and query-string manipulation at viewer events — no cold starts and lower per-invocation cost. Reserve Lambda@Edge for complex logic or origin-event work that needs Node.js/Python runtimes, larger memory, or request-body access.

Additional Best Practices

Beyond the per-feature guidance above, these operational habits round out a production-grade CloudFront deployment.

Enforce HTTPS at the edge

Redirect viewers to HTTPS and use an ACM viewer certificate in us-east-1; origin certificates follow the origin service/Region requirements.

Keep S3 origins private

Use OAC with an explicit bucket policy scoped to the distribution. An S3 website endpoint is a custom origin and cannot use OAC/OAI.

Use managed policies where they fit

Prefer managed cache and origin-request policies. Forward values to the origin without adding them to the cache key when they do not change the response.

Version your objects

Prefer content-addressed or versioned object names for releases. Use invalidations for urgent removals, not as the routine cache-busting mechanism.

Test origin failover

Configure origin groups for eligible failure modes, and test that the secondary origin has equivalent content, capacity, and security controls.

Protect origins from direct access

Use VPC origins, OAC where supported, or an origin-verification control such as a secret custom header plus WAF; rotate shared secrets.
