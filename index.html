AWS Best Practices Documentation

A curated, structured reference guide covering commonly used AWS services and architecture patterns. It is not an exhaustive catalog of AWS services — each document focuses on the practices that matter most in real workloads. The site is also available at GitHub Pages.

How to use this documentation

  1. Navigate by service category using the cards above.
  2. Search for specific topics using your editor's search functionality.
  3. Cross-reference related services — each document links to complementary best practices, so pairing a service guide with its architecture pattern doc (for example High Availability & DR Patterns alongside RDS Best Practices) gives the full picture.
  4. Apply progressively — start with the critical security practices in IAM Best Practices and VPC Best Practices, then optimize for cost and performance.

Deploying the documentation site

The repository includes a GitHub Pages workflow at .github/workflows/pages.yml. It builds the Markdown with Jekyll and deploys the result whenever a commit is pushed to main.

To enable the first deployment:

  1. Push these files to GitHub.
  2. Open Settings → Pages in the repository.
  3. Under Build and deployment, set Source to GitHub Actions.
  4. Open Actions and follow the Deploy documentation to GitHub Pages run.

For the current repository name, the default site URL will be https://alexanderbesss.github.io/AWS_best_praactices/. GitHub will also show the final URL in the deployment summary.
