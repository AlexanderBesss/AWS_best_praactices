S3 Best Practices

Amazon S3 is the foundational object storage service for AWS, providing durable, scalable, and cost-effective storage for virtually any workload. Storage decisions directly impact your security posture, application performance, and cloud spend — this guide consolidates the considerations that matter most so teams make informed choices rather than defaulting to the simplest option.

Data Lifecycle Policies

Automating data movement across storage classes prevents costs from spiraling as objects age and access patterns change. Without lifecycle policies, data accumulates in expensive tiers indefinitely.

Lifecycle Rules

The following schedule is an illustrative seven-year log-retention policy. Choose transitions and expiration based on access patterns, recovery needs, regulatory retention, and minimum-storage-duration charges.

ActionTransition TargetDays After CreationDescription
TransitionS3 Standard-IA30Move infrequently accessed data
TransitionS3 Glacier Flexible90Archive older data
TransitionS3 Glacier Deep Archive365Long-term retention
Expire—2555Delete after the seven-year retention period
Abort Incomplete Multipart Upload—7Clean up failed uploads

Lifecycle Policy Example

{
  "Rules": [
    {
      "ID": "archive-and-expire",
      "Status": "Enabled",
      "Filter": { "Prefix": "logs/" },
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" },
        { "Days": 365, "StorageClass": "DEEP_ARCHIVE" }
      ],
      "Expiration": { "Days": 2555 }
    },
    {
      "ID": "abort-incomplete-uploads",
      "Status": "Enabled",
      "Filter": { "Prefix": "" },
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
    }
  ]
}

Security

S3 is frequently the target of misconfiguration-based data breaches, making security controls non-negotiable. Each control addresses a distinct attack vector, and layering them provides defense in depth.

Warning

Enable S3 Block Public Access at the account level as your first action on any new account. Publicly accessible buckets are a leading cause of S3 data breaches, and this control is marked CRITICAL for a reason.

Data Consistency

Knowing the consistency guarantees is critical for designing applications that read back their own writes or rely on listing accuracy. S3's strong consistency model simplifies many patterns, but edge cases still exist.

OperationConsistency ModelNotes
READ after WRITEStrong consistencySince December 2020
READ after LISTStrong consistencySince December 2020
DELETEStrong consistencyObject immediately unavailable
List operationsStrong consistencyAll prefixes and objects
Note

Since December 2020, S3 provides strong consistency for all operations — you can read an object immediately after a successful PUT, and LIST results reflect the latest state. Designs that once needed read-after-write polling no longer do.

Replication

Replication is the backbone of disaster recovery and data sovereignty requirements, but it has prerequisites and limitations that must be planned for upfront. Configuring it reactively leaves a gap of unprotected data until catch-up replication completes.

Replication Types

TypeDirectionLatencyUse Case
Cross-Region (CRR)One region → anotherMinutesDisaster recovery, compliance
Same-Region (SRR)One bucket → anotherMinutesData segregation, workload optimization
One-waySource → DestinationMinutesStandard replication
Multi-Region Access PointRoutes requests to one or more Regional bucketsDepends on routing and bucket healthGlobal endpoint and active-active or failover routing; it does not replicate data by itself

Replication Requirements

Missing any prerequisite silently breaks replication, leaving teams unaware of the gap until a failure occurs. Verify each requirement before relying on replication for business continuity.

RequirementDescription
Enable versioningRequired on both source and destination
S3 Replication RoleIAM role with required permissions
Object ownershipPrefer Bucket owner enforced; use replica-owner override only for legacy ACL requirements
EncryptionSSE-KMS and DSSE-KMS objects require explicit replication configuration and KMS permissions
Existing objectsLive replication covers new writes after configuration; use S3 Batch Replication for existing objects
Object sizeSubject to the S3 object maximum of 5 TB
Warning

Live replication only covers objects written after configuration. If you enable replication on an existing bucket, run S3 Batch Replication to backfill — otherwise your DR copy is incomplete until catch-up finishes.

Cost Drivers

S3 pricing varies by Region, storage class, request category, retrieval amount, data transfer path, object count, and optional features. Do not compare storage price alone: minimum-duration charges, per-object metadata, retrieval, early deletion, replication, and KMS request charges can dominate small-object or short-lived workloads. Use the S3 pricing page and AWS Pricing Calculator for your deployment Region. Broader budgeting approaches are covered in the Cost Optimization guide.

Object Lock Modes

The two lock modes serve different threat models — governance protects against operational mistakes, while compliance defends against determined adversaries, including privileged users.

Governance

Objects are protected from deletion and overwrite, but users with the s3:BypassGovernanceRetention permission can override the retention. Best for protecting against accidental deletion.

Compliance

Objects cannot be deleted or overwritten by anyone, including the root user, once the mode is set. Required for regulatory compliance regimes such as SEC and HIPAA.
